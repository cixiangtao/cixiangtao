# Contribution profile: original snk + github-profile-3d-contrib

This implementation composes the two upstream projects. It replaces the earlier
handwritten snake and charts. Both profile READMEs embed the generated overview while retaining the personal
website link, introduction, project table, and toolbox. The generator itself only
writes the overview assets; it does not alter README content or the website.

## What is reused

| Component | Implementation |
| --- | --- |
| Snake route, body, cell eating, collected-cell bar and loop | Official `generate-snake-animation@3.5.0`, published by [Platane/snk](https://github.com/Platane/snk) |
| Data aggregation, primary-language commit attribution, Stars and Forks totals | Unmodified `aggregate-user-info.ts` from [github-profile-3d-contrib](https://github.com/yoshi389111/github-profile-3d-contrib) |
| Language doughnut and contribution radar | Unmodified `create-pie-language.ts` and `create-radar-contrib.ts` from that project |
| Theme CSS, settings and formatting helpers | Unmodified upstream files |

The vendored files are pinned to commit
`e235d118909be71eb7edb05482a3de4e76156df3` (0.9.3).
Their MIT notice is retained in
`profile-activity/vendor/github-profile-3d-contrib/LICENSE`.
`UPSTREAM.json` records exact paths and SHA-256 hashes. The snk implementation is
an installed npm dependency, not a locally copied or rewritten solver.

Local changes are limited to combining the outputs into one SVG, desktop/mobile
layout, theme contrast, month labels, accessibility, and exposing exact values
that upstream otherwise puts in hover titles. The radar's geometry and logarithmic
scale are unchanged. The language chart's ring and legend are unchanged except
for directly visible percentages. The 3D calendar is replaced by original snk's
2D calendar.

## Generate and preview

Requires Node.js 22.12+ and either `GITHUB_TOKEN` or an authenticated `gh` CLI.

```sh
npm ci --prefix scripts/profile-activity
node scripts/generate-profile-activity.mjs cixiangtao
npm test --prefix scripts/profile-activity
python3 -m http.server 8765 --bind 127.0.0.1
```

Open <http://127.0.0.1:8765/output/profile-activity/preview.html>.

The outputs include desktop `light.svg` / `dark.svg`, vertically arranged
`light-mobile.svg` / `dark-mobile.svg`, and the two original snk SVGs
`snake-light.svg` / `snake-dark.svg` for direct comparison. The original snk
animation uses 100ms per step; loop duration depends on its computed route.
No JavaScript or external resources are needed to display these files.

API and render work finishes before the prior output files are replaced. Tokens
are kept in process memory and are not written into images, logs, or snapshots.
The generator does not store raw API responses or repository names.

## Data meaning

- Contribution counts and date range follow GitHub's default rolling year.
- The five radar axes show commits, issues, PRs, reviews, and created repositories.
  The original logarithmic scale is retained; exact counts appear on every axis.
- **Language shares are commit counts grouped by repository primary language**,
  following the upstream aggregator. They are not code bytes or per-file language
  analysis. GitHub returns at most 100 contributing repositories for this field.
  As upstream does, the pie shows the five largest languages and puts remaining
  and unattributed commits into `other`.
- Local attribution considers public repositories only, even if local credentials
  could see private repositories; private/unattributed counts remain unclassified.
- Stars and Forks sum all owned public repositories, including archived and forked
  repositories. All repository pages are read; totals are not capped at 100.
  These are current repository totals, not yearly contributions.
- Snake animation is generated by upstream's own API request. Statistics and snake
  are fetched consecutively; new contributions arriving between those requests
  may first appear together on the next generation.

## Daily updates and checks

`.github/workflows/sync-profile-projects.yml` refreshes both the project tables and
contribution assets every day at **04:37 Asia/Shanghai**, or via a manual workflow
run. It uses the existing `PROFILE_SYNC_TOKEN` to create its update PR and the
built-in `GITHUB_TOKEN` for public read-only API calls. The credential is already
configured for this repository; if unavailable, the existing workflow explicitly
skips the update. The automation waits for the required protected-branch checks
before merging. It does not push directly to `main`.

`.github/workflows/check-profile-activity.yml` validates the upstream integration
and source hashes on relevant pull requests and pushes. Tests use fixed fixture
data and do not require API credentials. The website's existing design system
and deployment workflow are unchanged.
